# managing-zotero Skill 设计规格

- 日期：2026-08-20
- 状态：设计已批准；Zotero 10 本地授权兼容性已实机验证
- 适用环境：Windows 10（64 位）、Zotero 10（64 位）、Codex 桌面端
- 定位：通用 Zotero 文献管理 Skill，支持按研究方向加载领域配置；首个内置配置为微波转动光谱与计算化学

## 1. 目标

`managing-zotero` 是一项通用 Zotero 文献管理 Skill。它把文献检索、证据核查、主题归档、简要文献卡、全文深度报告和去重控制连接成一条可审计流程，并允许按研究方向加载独立的领域配置。微波转动光谱与计算化学是第一版内置配置，不是核心 Skill 的适用范围限制。整个 Skill 保持以下边界：

1. Zotero 中的任何新建、更新或附件操作都必须在执行前向用户展示预览并取得明确同意。
2. 不直接写入 `zotero.sqlite`，只使用 Zotero 10 官方本地 API。
3. 不替代现有文献检索、精读、领域分析和论文写作 Skill，而是负责把它们的可靠结果有序写入 Zotero。
4. 不把摘要阅读伪装成全文阅读；无法合法获取全文时明确标记证据边界。
5. 不自动删除、合并或覆盖用户已有资料。

## 2. 使用场景

### 2.1 Codex 检索到的新文献

用户提出某一分子、团簇或实验问题后，Codex 可调用已有的文献检索与阅读能力得到候选文献。`managing-zotero` 随后负责：

1. 规范化题名、作者、期刊、年份、DOI 等元数据。
2. 在 Zotero 中检查重复项和已有条目。
3. 按通用字段及当前启用的领域配置整理标签和简要文献卡。
4. 向用户展示拟创建或拟更新内容。
5. 获得用户同意及 Zotero 本地授权后写入。
6. 写入后重新读取并核对实际结果。

### 2.2 用户自行加入 Zotero 的文献

用户可指定某个 Collection 或具体条目，让 Skill 检查并补充元数据、标签、附件状态或 Codex 文献卡。Skill 不在后台扫描整个文献库，也不会在未指定范围时批量改写条目。

### 2.3 论文证据整理

Skill 可把已经核实的实验与理论信息整理为简要 Zotero 子笔记，并把详细精读报告、对照表或论文证据表保存在用户批准的 D 盘项目目录中。Zotero 笔记与外部报告之间记录可追踪的文件路径或标识。

## 3. 通用核心与领域配置

### 3.1 通用核心

核心 Skill 只负责 Zotero 连接、元数据规范化、查重、Collection 管理、标签与笔记、附件状态、写入确认、回读验证和审计记录。核心不硬编码具体学科的实验参数、计算方法或证据标准。

领域配置负责定义某一研究方向需要的受控标签、文献卡字段、Collection 默认组织方式和证据核查清单。没有启用领域配置时，Skill 仍可作为通用 Zotero 管理工具运行。

### 3.2 默认微波光谱配置

对于当前用户，默认启用微波转动光谱与计算化学配置。本 Skill 是该工作中的文献与证据管理层，不改变用户的计算和谱线指认流程：

`GaussView 初始构型 → CREST 构象搜索 → Gaussian 优化与 A/B/C、偶极矩、能量 → 必要时 ORCA → PGOPHER/SPFIT 实验拟合与构象确认`

该配置主要提供三类支持：

- 在计算前，按分子体系收集相似复合物、实验频段、构象与计算方法的先例。
- 在指认中，归档理论常数、实验常数、选择定则、同位素或超精细证据的出处。
- 在写论文时，区分“可作为背景引用”“可支持方法选择”“可支持结构指认”“仍需补充全文或独立证据”的文献。

理论值与文献先例只能用于候选筛选和证据增强，最终实验构象指认仍需依赖拟合残差、选择定则、相对强度以及可用的同位素、超精细或其他独立证据。

## 4. Collection 组织规则

核心 Skill 允许用户按课题、项目、样品、分子体系或其他明确单位组织 Collection。当前用户启用微波光谱配置时，采用以下默认规则：

1. 每个新的分子或团簇体系建立一个独立 Collection，例如 `乙醇胺–水（1:1）`；其他领域配置可定义自己的默认组织单位。
2. 新建 Collection 前必须询问用户；若已存在同主题或同体系 Collection，则优先复用并展示其名称与标识。
3. 每次把新条目、已有条目、附件或笔记写入某个 Collection 前，都必须再次询问用户。
4. Collection 名称应保留清晰的化学计量关系；不同化学计量数或不同聚集程度原则上分开管理。
5. Skill 不擅自重命名、移动或删除用户已有 Collection。

## 5. 条目元数据、通用状态与领域标签

### 5.1 标准元数据

在来源支持时，维护以下 Zotero 标准字段：

- 题名
- 作者
- 期刊或会议来源
- 年份
- 卷、期、页码或文章号
- DOI
- URL
- 语言
- 摘要

元数据优先采用 DOI 注册机构、出版社页面、数据库记录或论文正文等可核验来源。不同来源冲突时，不静默覆盖，须在预览中指出。

### 5.2 受控标签与领域扩展

标签采用“类别：值”的形式。仅当论文本身或可靠元数据明确支持时添加，不依据题名进行过度推断。`状态` 类标签属于通用核心；`体系`、`实验`、`证据` 和 `计算` 类标签由微波光谱领域配置提供：

- `体系：单体`
- `体系：二聚体`
- `体系：多聚体`
- `实验：CP-FTMW`
- `实验：MB-FTMW`
- `实验：毫米波`
- `证据：同位素`
- `证据：超精细`
- `证据：内转动`
- `证据：振动卫星`
- `计算：CREST`
- `计算：Gaussian`
- `计算：ORCA`
- `计算：VPT2`
- `计算：相对论`
- `状态：待获取全文`
- `状态：全文已核查`
- `状态：已精读`
- `状态：可用于论文`

其他领域配置可提供自己的受控标签。无论启用何种配置，第一版都不得清空或批量替换用户自定义标签。

## 6. Zotero 简要文献卡与领域模板

核心 Skill 的默认子笔记标题为 `Codex｜文献卡`。启用微波光谱配置时，为适合整理的条目创建或更新以下领域子笔记：

`Codex｜微波光谱文献卡`

微波光谱文献卡根据可获得的证据选择性包含：

1. 与当前分子体系或研究问题的相关性。
2. 实验方法、频率范围和观测物种。
3. 构象、氢键拓扑或团簇结构描述。
4. 转动常数 A/B/C、偶极矩分量、离心畸变、超精细和同位素信息的可用性。
5. 计算程序、方法、基组和能量层级。
6. 谱线或构象指认所依赖的证据。
7. 对当前计算、实验指认或论文写作的具体用途。
8. 证据状态：仅元数据、仅摘要、全文已核查或已深度精读。
9. D 盘详细报告的路径或关联标识。

准确数值、逐字表述和页码只有在相应 PDF 或合法全文已经核实后才能写入。若只有摘要，文献卡必须明确写明“基于摘要”，不得填充正文才可能提供的细节。

Skill 不覆盖用户个人笔记。若条目已存在当前领域配置对应的 Codex 文献卡，应通过稳定标识识别，仅在展示差异并获得同意后更新该笔记。

## 7. 全文与附件策略

1. 优先使用开放获取、机构已授权或用户已合法持有的 PDF。
2. 不绕过付费墙、登录限制、验证码或访问控制。
3. 有关文献但没有可合法获取 PDF 时，仍可在用户同意后保存元数据和 DOI，并添加 `状态：待获取全文`。
4. 无全文时只能进行元数据级或摘要级概述，不能标记为 `全文已核查`、`已精读` 或 `可用于论文`。
5. PDF 下载或附件写入失败不阻止已批准的元数据写入；实际状态必须在结果中明确报告。
6. 用户后来手动加入 PDF 后，可指定该条目再次运行全文核查和文献卡更新流程。
7. 第一版对用户批准后保存在稳定 D 盘科研目录中的 PDF，默认创建 Zotero `linked_file` 附件并在预览中显示绝对路径；不把临时下载文件或任务脚本作为附件。移动源 PDF 会导致链接失效，因此写入前必须确认文件已位于最终目录。
8. 第一版不实现需要远程存储交互的 Zotero 二进制文件上传；以后若增加 `stored_file` 模式，需另行设计、测试并取得用户批准。

## 8. 重复项识别与复用

重复项匹配按以下证据综合判断：

1. DOI 精确匹配。
2. PMID 或 arXiv 标识匹配。
3. 规范化题名、主要作者和年份的组合匹配。
4. 必要时结合期刊、卷页或文章号人工复核。

发现已有条目时，默认做法是复用现有条目，并在预览中提出可选动作，例如加入当前 Collection、补充缺失 PDF、添加受控标签或创建 Codex 文献卡。第一版不自动合并或删除重复项，也不因题名近似就覆盖已有元数据。

## 9. 写入确认协议

任何会改变 Zotero 的动作都执行两层确认：

### 9.1 Codex 预览确认

执行前向用户展示：

- 目标 Library 与 Collection。
- 拟新建、复用或更新的条目数量。
- 每个条目的关键身份信息和重复判断。
- 拟写入或修改的元数据、标签、附件和笔记摘要。
- 无全文、元数据冲突、疑似重复或版本冲突等风险。
- 本批操作中明确不会执行的删除、合并或覆盖行为。

只有用户明确同意后才能调用写入流程。用户若修改范围，必须生成新的预览。

### 9.2 Zotero 本地授权

Zotero 10 本地 API 的写入授权由 Zotero 自身确认界面控制。用户拒绝或授权失败时，Skill 不进行任何替代写入。

### 9.3 默认批量上限

一次预览默认最多涉及一个 Collection 和 10 篇文献。文献较多时，先报告候选总数、重复项数量、全文可用性和主要风险，再询问用户是扩大本批上限还是分批处理。无论选择哪种方式，每一批都需单独确认。

## 10. 本地 API 与安全边界

1. 仅连接 `http://localhost:23119/api/`，不把 Zotero 凭据或库内容发送给非必要服务。
2. 不保存 Zotero 密码；本地 API 不要求用户登录 Zotero 账号才能使用本机库。
3. 不直接读写 `zotero.sqlite` 进行修改。
4. 第一版不调用 DELETE，不删除 Collection、条目、附件、标签或笔记。
5. 第一版不自动合并重复项，不清空标签，不覆盖用户个人笔记。
6. 第一次真实写入前提醒用户备份 Zotero 数据目录或确认已有可用备份。
7. Zotero 未运行、本地 API 未启用或用户拒绝授权时，流程停留在预览或只读阶段。

### 10.1 能力检测与授权兼容

Zotero 10 本地写入在当前版本中仍处于接口过渡阶段，Skill 不仅依据版本名称判断能力，而是在每个会话中执行运行时检测：

1. 先对 `/api/` 发送只读 `GET`，读取 `Zotero-API-Version`、`Zotero-Schema-Version` 和 `Zotero-Server-ID`。
2. 缺少 Server ID、API 版本不兼容或授权端点不可用时，明确降级为只读模式，不尝试 Web API、Connector API 或 SQLite 替代写入。
3. 调用 `POST /api/local/authorize` 前必须先得到用户对“授权测试”或具体写入批次的明确同意，并把应用名显示为 `Codex managing-zotero`。
4. 第一版默认使用“仅允许一次”的本地授权。返回的本地 API Key 仅保存在当前进程内存中，不输出、不写入日志、不写入环境变量或配置文件，并在一次写入请求后丢弃。
5. 一个批次需要多个 API 写请求时，每个请求分别取得授权；不通过持久保存密钥来减少 Zotero 弹窗。
6. 用户拒绝、超时、接口返回 `401/403/405/501` 或 Server ID 改变时，停止相应写入并报告实际状态。

### 10.2 2026-08-20 实机验证结果

在用户明确批准下完成了两项不改动文献库的测试：

- `/api/` 只读连接返回 HTTP 200、API 版本 3、Schema 版本 44，并提供 Server ID。
- `/api/local/authorize` 返回 HTTP 200；用户选择“仅允许一次”，授权成功。

测试没有读取具体 Collection 或文献，没有执行条目、Collection、附件或笔记写入。返回密钥未显示、未保存，并随测试进程结束而丢弃。这证明当前电脑上的 Zotero 10 支持计划采用的本地弹窗授权流程，但 Skill 仍须保留运行时能力检测以保持普适性。

## 11. 处理流程

完整数据流为：

`用户请求 → 文献检索/精读 Skill → 候选文献与合法全文 → 元数据规范化 → Zotero 查重 → 写入预览 → 用户同意 → Zotero 本地授权 → 创建或复用 Collection → 写入元数据/附件/标签/笔记 → 回读验证 → D 盘详细报告与审计记录`

内部划分为五个组件：

1. **连接检查**：确认 Zotero 本地 API、版本、当前 Library 和写入能力。
2. **候选规范化**：统一标识符、作者、题名、期刊和全文状态。
3. **领域配置加载**：根据用户选择加载 Collection 规则、受控标签、文献卡模板和证据清单；未选择时使用通用核心。
4. **查重与分类**：区分新条目、可复用条目、疑似冲突条目和不可安全判断条目。
5. **确认与写入**：生成差异预览，只执行用户批准的动作。
6. **回读验证**：按 Item Key 和版本号核对 Collection、字段、标签、附件与 Codex 笔记。

## 12. 异常与恢复规则

- **连接失败**：报告 Zotero 未运行、本地 API 不可用或端口异常，不尝试直接数据库写入。
- **授权被拒**：保持零写入并返回用户可理解的原因。
- **版本冲突**：若预览后条目版本发生变化，暂停该条目，重新读取并生成新预览。
- **元数据冲突**：保留现有值并展示来源差异，等待用户选择。
- **PDF 失败**：保留已批准的元数据和 `状态：待获取全文`，报告失败原因。
- **部分写入**：立即回读实际状态，逐项报告成功与失败，不进行无提示的盲目重试。
- **疑似重复但证据不足**：不新建也不合并，列入人工确认清单。
- **单条异常**：暂停受影响条目；其他条目是否继续以本批预览中批准的策略为准。

每次真实写入在用户批准的 D 盘任务目录中生成追加式审计记录，至少记录时间、目标 Collection、Item Key、操作类型、预览摘要、批准状态、写入结果和回读结果。审计记录不保存账号密码或受版权保护的全文内容。

## 14. 测试与验收

### 14.1 模拟 API 测试

在不改动真实 Zotero 库的模拟环境中验证：

- 本地 API 连接和服务器身份检查。
- 写入授权状态处理。
- Server ID、授权端点和写入能力探测；不支持时安全降级为只读。
- 本地 API Key 不输出、不持久化，并在单次写请求后丢弃。
- DOI、PMID、arXiv 和题名作者组合查重。
- 未得到用户批准时绝不调用写入。
- 预览后版本冲突会中止受影响条目。
- 部分失败能被回读并准确报告。
- 代码中不存在直接 SQLite 修改和 DELETE 路径。
- PDF 只有在位于用户批准的最终 D 盘目录后才创建 `linked_file` 附件。
- 通用核心在不加载微波光谱配置时仍能完成安全的 Zotero 管理流程。

### 14.2 Skill 行为测试

按 Skill 测试驱动流程先记录没有本 Skill 时代理可能出现的失败，再加载 Skill 进行同一压力场景测试。重点验证：

- 代理不会跳过 Collection 与逐批写入确认。
- 摘要级阅读不会被标记为全文精读。
- 已有 DOI 不会创建重复条目。
- 用户个人笔记和自定义标签保持不变。
- 文献量超过默认上限时会先询问批次策略。
- 微波光谱字段只在启用相应领域配置时出现，不污染通用核心。

### 14.3 真实 Zotero 冒烟测试

只有在用户另行批准后才进行。测试范围限定为一个明确批准的新测试 Collection 和 1–2 个测试条目。写入后验证：

- Collection 名称和层级正确。
- 条目元数据与批准预览一致。
- 重复 DOI 被复用而非重复创建。
- PDF 缺失流程正确添加待获取状态。
- Codex 子笔记没有覆盖个人笔记。
- 回读到的 Item Key、版本、标签和附件状态完整。

### 14.4 结构验证

完成实现后运行 Codex Skill 快速验证工具，检查 `SKILL.md`、元数据、目录结构和代理配置是否合法。

## 15. 第一版明确不做的事情

- 不后台监控或扫描整个 Zotero 库。
- 不自动删除、合并、清空或批量重命名。
- 不绕过版权或访问控制获取全文。
- 不在 Zotero 中保存完整深度报告或大批计算结果。
- 不替代人工实验谱拟合、最终构象指认或论文作者的科学判断。
- 不自动把每篇相关文献标记为“可用于论文”。

## 16. 完成标准

第一版只有在以下条件同时满足时才可称为完成：

1. Skill 文件结构完整并通过结构验证。
2. 模拟 API 测试全部通过。
3. 行为测试证明关键约束能改变代理行为。
4. 所有写入路径都要求 Codex 预览确认和 Zotero 本地授权。
5. 没有直接数据库修改、DELETE、自动合并或无提示覆盖路径。
6. 用户审阅并批准本设计及后续实施计划。
7. 若用户选择进行真实冒烟测试，其实际结果已回读核实并明确报告。
